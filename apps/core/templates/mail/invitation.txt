AUTOESCAPE OFF, AND IT IS LOAD-BEARING. This is a plain-text body: there is no
HTML here for escaping to protect, and escaping actively breaks it. The
credential-setting link carries a query string — `?userID=…&code=…` — and
Django's default rendering turns that `&` into `&amp;`, which a text client
shows literally. The invited person copies a URL that does not work, which is
the exact class of dead end this template exists to close. Caught by
`test_the_email_leads_with_the_credential_setting_link`, which is why that test
asserts the link byte for byte rather than checking that it is "in there
somewhere".

The HTML alternative is a different matter and keeps its escaping: `&amp;`
inside an `href` is correct, and it is what makes the attribute well-formed.
