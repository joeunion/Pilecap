# The instrument census — what each one can and cannot see

> **The population is DERIVED, then pinned. Do not hand-edit the list.**
>
> ```
> python3 scripts/goalpost_scan.py --census
> ```
>
> re-derives it and **exits 2 when a file exists without a row** (or when a row
> names a file that is gone or no longer executable, or when a cell answers
> without a citation). A hand-kept list is the class this census exists to
> refuse — it is a second copy that agrees today.
>
> **THIS FILE IS THE TEMPLATE'S HALF. A product's own instruments go in
> `docs/product/instruments.local.md`** — the same five-column `Instrument`
> table, read beside this one by the same census, so a product never edits a

> census output is byte-identical to a tree that has never heard of the drawer,
> and the template never ships one (`publish.sh` § R0). The drawer list and its

>
> **The derivation** (`scripts/goalpost_scan.py::population`): every **executable**
> file git knows about — tracked, or untracked and not ignored — **outside
> `apps/`, `config/`, `.venv/` and `.git/`**, plus `quality/gate.py`, plus every
> management command whose name matches `CENSUS_COMMANDS` — today
> `introspect|integrations|roads|*_audit|*_sweep|*_reconcile|*_measure` — plus the pinned
> reporting surfaces that are not executables (`CENSUS_PINS` — today

> and which is sourced rather than run).
>
> **The command half is matched on the NAME, and `--census` says so on every
> run.** A command that prints a verdict under a name the pattern does not
> carry owes no row, which is a blind spot and not a clean bill, so the reader
> also reads the verdict grammar every command module declares
> (`CENSUS_VERDICT_GRAMMAR` — a `raise SystemExit` after the report, the exit
> status being the finding) and NAMES the commands the grammar finds outside
> the population. Those lines are candidates a person judges, never rows the
> census manufactures; the population itself stays the pattern.
>
> **A SOURCED LIBRARY IS NOT AN INSTRUMENT, AND THE CENSUS SAYS SO BY
> REFUSING IT A ROW.** `scripts/docs_legs.sh` holds the three `--fast` census
> bodies — `adr-census`, `dangling-docs`, `ci-env` — and
> `scripts/archaeology_lib.sh`, `scripts/secrets_scan.sh`, `scripts/db.sh` and
> `scripts/gate_refuse.sh` are its neighbours: mode
> 644, sourced and never run, reporting no verdict of their own. The caller
> owns the exit status, so the caller is the instrument and owes the row
> (`scripts/check.sh` and `scripts/publish.sh` both have one). The population
> above is EXECUTABLES plus `CENSUS_PINS`, so a row naming one of these files
> is a **ghost** and the census exits 2 on it — which is the mechanism, not an
> oversight: adding a row here to be tidy would break the very census the row
> was meant to satisfy. Where a sourced body's blind spots are declared is in
> the body's own header, and its cases are the module's — for these four,
> `quality/tests/test_docs_legs.py`.
>
> **It began as two directory listings**: `scripts/` and `scripts/githooks/`,
> which is to say the census could only see instruments where somebody had
> already thought to look. `deploy/` had meanwhile grown a readiness prober, an
> alert census, three alert tools and two brooms, and not one of them owed a
> row. Widening it is the same move the population itself is: derive, do not
> list. **Where it still does not look, and why, is in
> `scripts/goalpost_scan.py::CENSUS_NOT_LOOKED_AT` — the four prefixes, each
> with its reason.**

## Why this file exists (ADR gate-3)

Three instruments in one day were found judging inputs they could not read:
one took a verdict from a queryset no door actually issues, another printed a
cause it had not proven, and `loop_health.py` scored a vocabulary it never
matched while a newly closed cycle was invisible to it. None of the three was
silent about being an instrument; all three were silent about being blind.
**An instrument that reports a verdict a human or a gate acts on is held to
the same standard as a rule: it declares its blind spots, and it fails loud
when it cannot see.**

## The four questions

Every row answers with a **`file:line`**, never with an adjective:

1. **nothing-wrong vs could-not-look** — does the instrument distinguish "I
   looked and it is fine" from "I could not look"?
2. **loud or silent** — when it cannot look, does it say so with a status a
   caller cannot mistake for a pass?
3. **declares what it does not cover** — is the blind spot written down beside
   the code, or discovered later?
4. **built because** — the hazard that made this instrument worth building,
   and where it went.

**What a row cannot tell you:** every cell is a *claim with a citation*. The
re-deriver checks that the citation has the shape of a `file:line`; it never
checks that the line says what the cell says. A wrong answer that cites a real
line passes, and reading them is a standing rotation, not a script's.

**"Reports no verdict" is a legal answer.** The population is derived, so a
plumber (`serve.sh`, `worker.sh`) owes a row saying it is a plumber. The census
cannot tell a reporter from a plumber; it can only tell a listed file from an
unlisted one.

(`# >>> drive: pm_fold >>>`, `# >>> exit-guard >>>`), a function name, or a
quoted sentence the reader can `grep` — and not line numbers. An anchor
survives an edit above it; a number does not, and it goes stale INVISIBLY,
which is the property that makes it worse than no citation at all. **Columns 2 to 4 still carry numbers, and that is not a lapse**:

what each is for — the numbers are the census's machine-checkable floor, the

## Findings this census raised

Three were **fixed at the census's birth** (the one-seed×2 leg, the loop-health
reader, and the Temporal census becoming a gate leg). Two more were reported
and left, and **both are closed now**:

- **F-1 · an absence exited like a violation — CLOSED**. "the client generator
  was not found" and "the database does not exist" were *could-not-look*
  answers reported with exit 1, the code a caller reads as "I looked, and it
  is wrong". Both are exit 2 now, and each script's header says which of its
  own refusals is which and why (`scripts/gen_client.sh:23-30`,
  `scripts/backup.sh:176-188`). The distinction is drawn where it matters
  rather than everywhere: `backup.sh`'s too-small-dump refusal stays exit 1,
  because there the script DID look — it made an object and the object is not
  a backup.
- **F-2 · a partial setup exited like a complete one — CLOSED**. When the
  identity-provider seed did not complete, `setup.sh` said so on stderr and
  then printed "Setup complete." and exited 0. The failure is now remembered,
  the closing banner names what did not happen, and the exit is 1
  (`scripts/setup.sh:825-848`, `scripts/setup.sh:1051-1053`). The REST of setup
  still runs — a laptop with no provider token should still end up with a
  working stack — because what was wrong was the verdict, not the behaviour.

Both were honesty-of-status findings, not correctness findings: nothing computed
the wrong answer, and both instruments said the right words. What they got wrong
was the *code* a caller trusts — which is exactly the class ADR gate-3 names.
