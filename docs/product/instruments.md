# The instrument census — what each one can and cannot see

> **The population is DERIVED, then pinned. Do not hand-edit the list.**
>
> ```
> python3 scripts/goalpost_scan.py --census
> ```
>
> re-derives it and **exits 2 when a file exists without a row** (or when a row
> names a file that is gone or no longer executable, or when a cell answers
> without a citation). A hand-kept list is the class this census exists to
> refuse — it is a second copy that agrees today.
>
> **The derivation** (`scripts/goalpost_scan.py::population`): every **executable**
> file git knows about — tracked, or untracked and not ignored — **outside
> `apps/`, `config/`, `.venv/` and `.git/`**, plus `quality/gate.py`, plus every
> management command whose name matches `introspect|*_audit|*_sweep`, plus the
> pinned reporting surfaces that are not executables (`CENSUS_PINS` — today
> `scripts/gate_ledger.sh`, whose line shapes are the verdict ledger's contract
> and which is sourced rather than run).
>
> **It began as two directory listings**: `scripts/` and `scripts/githooks/`,
> which is to say the census could only see instruments where somebody had
> already thought to look. `deploy/` had meanwhile grown a readiness prober, an
> alert census, three alert tools and two brooms, and not one of them owed a
> row. Widening it is the same move the population itself is: derive, do not
> list. **Where it still does not look, and why, is in
> `scripts/goalpost_scan.py::CENSUS_NOT_LOOKED_AT` — the four prefixes, each
> with its reason.**

## Why this file exists (ADR gate-3)

Three instruments in one day were found judging inputs they could not read:
one took a verdict from a queryset no door actually issues, another printed a
cause it had not proven, and `loop_health.py` scored a vocabulary it never
matched while a newly closed cycle was invisible to it. None of the three was
silent about being an instrument; all three were silent about being blind.
**An instrument that reports a verdict a human or a gate acts on is held to
the same standard as a rule: it declares its blind spots, and it fails loud
when it cannot see.**

## The four questions

Every row answers with a **`file:line`**, never with an adjective:

1. **nothing-wrong vs could-not-look** — does the instrument distinguish "I
   looked and it is fine" from "I could not look"?
2. **loud or silent** — when it cannot look, does it say so with a status a
   caller cannot mistake for a pass?
3. **declares what it does not cover** — is the blind spot written down beside
   the code, or discovered later?
4. **built because** — the hazard that made this instrument worth building,
   and where it went.

**What a row cannot tell you:** every cell is a *claim with a citation*. The
re-deriver checks that the citation has the shape of a `file:line`; it never
checks that the line says what the cell says. A wrong answer that cites a real
line passes, and reading them is a standing rotation, not a script's.

**"Reports no verdict" is a legal answer.** The population is derived, so a
plumber (`serve.sh`, `worker.sh`) owes a row saying it is a plumber. The census
cannot tell a reporter from a plumber; it can only tell a listed file from an
unlisted one.

  the closing banner names what did not happen, and the exit is 1
  (`scripts/setup.sh:200-219`, `scripts/setup.sh:320-323`). The REST of setup
  still runs — a laptop with no provider token should still end up with a
  working stack — because what was wrong was the verdict, not the behaviour.

Both were honesty-of-status findings, not correctness findings: nothing computed
the wrong answer, and both instruments said the right words. What they got wrong
was the *code* a caller trusts — which is exactly the class ADR gate-3 names.

**The census is now a gate leg.** `check.sh --fast` runs
`goalpost_scan.py --census` as the `goalpost-census` leg, so an instrument that
lands without a row cannot reach a commit. The *scan* stays out of the gate —
ADR gate-3's ruling, unchanged — because a verdict's staleness is a judgement
about the register, not about this tree; the census is about this tree, reads no
database, and costs about a tenth of a second.

**Two findings this widening raised**, both recorded rather than fixed:

- **F-3 · `dns.sh` submits, and submitted is not live** (`deploy/dns.sh:71`).
  The script says so in its own success line and nothing makes a caller read it;
  only `dns.sh show` closes the gap. Not a defect — a DNS change genuinely is
  asynchronous — but a row that says "yes" to question 1 would be overclaiming.
- **F-4 · the prober is the one instrument that cannot report its own
  death** (`deploy/observability/alerts/prober.sh:57-61`). It is an
  infinite loop with no exit code anybody reads; its verdict is the event
  stream, so "the prober died" and "the prober sees nothing" look identical from
  the sink. That is the standing blind spot the deaf-sink alert exists for, and
  it belongs to the alert instrument rather than to this census.
