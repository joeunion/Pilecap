# ADR realtime-2

**The hierarchy reaches this door (ADR realtime-2):** the socket used to push every fanned event to one group per tenant while REST read the same rows through `visible_to`, so a branch-B seller's socket received branch-A's rows — two doors, one question, two answers. Now `Event` carries the **row's** organization (ADR realtime-2a: it rides the `EventOut` envelope, the one body both the webhook and socket doors are handed, so the fan-out narrows on a field it can see and the spine's bridge signature never changed); an org-bearing event is pushed to `org_group(tenant, org)` and **only** an org-less one to the bare tenant group; and a consumer joins its hat's **subtree** org groups at connect — the socket's half of house rule 24, narrowing *subscriptions* where REST narrows rows, downward-only and failing closed on an unresolved hat. A flat product is a depth-one tree whose root hat joins three constant groups, so the depth-one property is preserved. Every consumer also joins `user_group(user_id)` **FIRST, before either of its reads** (R4 F3 — a narrowing that commits while `connect` is still resolving would otherwise kick into a group the connection has not joined, and the kick is lost), and the bridge name **`realtime.kick`** (shape `KicksUser`) closes that group's sockets — connect-time-only auth is right for a channel that stays open for hours and wrong the moment a token is revoked, so revocation and erasure reach the connection instead of the connection eventually noticing. **Clause (d) has a second primitive: `realtime.kick_tenant`** (shape `KicksTenant`), a `KICK_TYPE` frame on `tenant_group`, because a tenant that is suspended or closed is not a fact about one person — `suspend_tenant` and `close_tenant` register it through `core.services.close_tenant_sockets_on_commit`, and before they did, a darkened tenant was refused at the next handshake and nowhere else while every live socket went on hearing (R4 F2). A **resume** kicks nobody: a widening takes nothing away, which is `kick_if_reads_narrowed`'s asymmetry one level up. **The channel is declaredly lossy and the seam is poll-on-reconnect** (`apps/realtime/bridge.py`'s docstring says it in full): no replay buffer, no cursor, none planned — a reconnecting client re-reads the REST list it cares about and treats a frame as a hint that something changed, and a hat switched mid-connection applies on reconnect. Rejected: **ancestor-chain publish** (cheaper joins, but the fan-out cost rides every emit including the socketless majority, where subtree-join cost rides only connected sockets) — RECORDED, with M4's measured join count at the 1,200-org hat as the trigger to revisit; a `visible_to` query per push (a DB read per event per connection — the N+1 the harness exists to refuse); connect-time-only auth with shorter tokens (narrows the window, closes nothing).
