# ADR comms-10

**A temporal lever delays; only a permanent one kills (ADR comms-10):** at the transport edge the consent recheck forks by the *kind* of lever that refused — suppression and withdrawn consent are facts about the person, so the message dies and the run closes **promptly**, through the finish seam and with no 72h `STATUS_WAIT` behind it (a `WorkflowRun` reading `running` for three days about a message refused in milliseconds was the ledger lying by laziness); quiet hours is a fact about the *clock*, so the run **sleeps to the recipient-local window-open on Temporal's timer and then re-runs the FULL wall** before handing anything over — the deferral is a road back to the wall, not around it, so a suppression landing during the sleep refuses at the second judgement. The deferral is a **designed delay and not a degraded state**: no announcement event, deliberately. Rejected: kill-and-re-enqueue (duplicates the row and restarts the policy), a poller over deferred messages (the run already exists and can wait — anything that waits is a workflow), keeping the 72h wait for refusals. trigger to revisit: deferral volume makes the sleeping-run population itself a cost, at which point one scheduled release workflow per window, as data.
