# ADR core-19

**ADR core-19 · context:** 429 was documented but no response header let a client back off before hitting it, and the throttle knows the numbers · **decision:** the `X-RateLimit-*` triple (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` as delta-seconds, matching `Retry-After`'s unit — no clock-skew ambiguity), stamped by the one middleware from what the throttle recorded on the request; the headers report the **binding** bucket (least remaining/limit ratio of the credential and tenant buckets) without naming it — which bucket binds is capacity information about the tenant's other credentials · **rejected:** the IETF RateLimit draft (`draft-ietf-httpapi-ratelimit-headers` — still a draft whose field names have churned across revisions; pinning it risks going stale as the draft churns, and adopting the RFC names once published is additive: stamp both through a window), per-bucket header pairs (a client can act on one number), headers on the MCP door (tools speak the refusal grammar; no HTTP header surface) · trigger to revisit: the draft becomes an RFC.
