{% load entrance %} {% comment %} THE ENTRANCE SHELL. Every page allauth serves — the sign-in page, the sign-out confirmation, the third-party failure and cancellation pages, the password and email flows, and every page a future allauth version adds that nobody here has read — renders inside this file. WHAT WAS WRONG. `templates/account/login.html` was the ONE override in the tree, so exactly one screen of the entrance chain was ours and the rest were allauth's unstyled defaults: no stylesheet at all, so a browser fell back to its own — Times New Roman, a 8px margin, and allauth's `Menu:` navigation list above the heading. Measured on the tree this landed against, the sign-out page served 1633 bytes whose entire visible text was "Menu: Account Connections Sign Out Sign Out Are you sure you want to sign out? Sign Out". A person who had just been invited into a product crossed five different visual registers in eight screens, and four of them were this absence. WHY THIS FILE AND NOT A PAGE-BY-PAGE SWEEP. Overriding page by page loses by census: allauth 65 ships thirty-odd entrance and management pages and adds more every minor version, so a hand list is a list that is already incomplete. The base is the seam allauth documents, and it is the only one that makes a page NOBODY HERE HAS EVER READ render in register by default. `templates/allauth/layouts/base.html` beside this file is the two-line re-parent that makes "the whole family" true rather than nearly true: allauth has THREE `base_entrance.html` files (`account/`, `socialaccount/`, `mfa/`) and two `layouts/` files, and only `account/base_entrance.html` — this one — is reached by overriding this name. Everything else funnels through `allauth/layouts/base.html`, which now extends this file, so one token block reaches every page in both families. WHAT IT IS ALLOWED TO STYLE. Surfaces whose WORDS this template also owns: the auth chain, the refusal pages, the invitation mail, the placeholder landing. Every product needs those identically and none differentiates on them. The moment it styles a surface whose content a product authors, it has shipped taste — the design ruling that the neutral bar is a mechanism, not decoration. NO EXTERNAL FETCH. No stylesheet link, no font file, no script. The font is `system-ui` — the no-choice choice — so there is nothing that can fail to load and nothing to be slow. The whole design is the token block below. TOKENS ARE DECLARED ONCE AND CONSUMED HERE. `--accent` is the ONE colour a product sets (`BRAND_ACCENT`), and the same declared value is what the hosted identity step will read, so the two match by construction rather than by somebody remembering. The rest are neutral by the neutral-bar ruling: the else-branch voice is FINISHED, not LOUD, and a placeholder accent that shouts teaches a clone that the colour is somebody else's problem. {% endcomment %} {% block head_title %}{% endblock head_title %} {% block extra_head %}{% endblock extra_head %} {% block body %}
