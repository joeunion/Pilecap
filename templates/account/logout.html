{% extends "account/base_entrance.html" %} {% comment %} Sign-out, in the house voice. allauth's own copy extends `account/base_manage.html` — the MANAGEMENT layout, not the entrance one — which is how a page every single person sees on their way OUT ended up in a different family from the page they came IN through. The re-parent at `templates/allauth/layouts/base.html` already makes it render in register; this file is here for the words, because "Are you sure you want to sign out?" is a question with no consequence attached and the person asking it usually wants to know what happens to the OTHER thing they are signed in to. It says so. This deployment signs people in through an identity platform, so signing out here ends the session HERE and leaves the platform session alone — which is exactly why the sign-in page after this is still a page and not a redirect (see `apps/accounts/templates/account/login_doors.html`: an auto-redirecting sign-in page turns this button into a loop). The form, the method and the hidden redirect field are allauth's, unchanged: sign-out is a POST because it is a state change, and a GET that ends a session is something any other site can point an image tag at. THE SENTENCE IS A FACT ABOUT THE DOOR, SO IT BRANCHES ON THE DOOR (design J5, A5.5). Under `hosted` the person's password is typed on the identity platform's own screens and that platform keeps a browser session of its own, which is why signing out here may not ask for a password again — the sentence this file has always carried. Under `ours` there is no such session to leave behind: our page opens a Session API session for the ceremony and CLOSES it at every exit, including every refusal and every *Never mind* (ADR ident-10), and there is no `{% templatetag openblock %} baseUri {% templatetag closeblock %} /logout` leg to render (ident-9, amendment 3). **What is still UNMEASURED is whether the OIDC round trip under login v2 leaves any cookie of the platform's in the browser** — measurement-kit item M7. Until it is measured the `ours` sentence is the design's intent and is written to claim only what this deployment controls: it says what happens to the session, and promises nothing about anybody else's. {% endcomment %} {% load i18n allauth entrance %} {% block head_title %}Sign out{% endblock head_title %} {% block content %} {% sign_in_door as door %}
